# Modbus Toolkit

Набор из 3 простых Windows-приложений для работы с неизвестным Modbus RTU устройством через RS485.

## Что есть

1. `modbus scan/app.py`
   Полный перебор параметров Modbus RTU: скорости, parity, stop bits, адреса, функции и регистры.
2. `server/app.py`
   Приложение для ПК2. Читает физический COM с адаптера RS485 и передает байты по TCP.
3. `client/app.py`
   Приложение для ПК1. Подключается к ПК2 по TCP и прокидывает байты в локальный COM порт.

## Схема работы

`RS485 устройство -> адаптер/COM на ПК2 -> server -> TCP -> client на ПК1 -> локальный COM -> Modbus Poll / Modbus Scan / другое ПО`

## Важное ограничение

`client` не создает виртуальный COM сам по себе. Для этого на Windows обычно нужен драйвер виртуальных COM-портов, например `com0com`.

Практический вариант:

1. На ПК1 установить `com0com`.
2. Создать пару виртуальных портов, например `COM30 <-> COM31`.
3. В `client` выбрать один порт пары, например `COM30`.
4. В Modbus-программе открыть второй порт пары, например `COM31`.

## Запуск из Python

```powershell
python -m pip install -r requirements.txt
python "modbus scan\app.py"
python "server\app.py"
python "client\app.py"
```

## Сканирование неизвестного китайского модуля

В окне `Modbus Scanner` можно перебрать:

- все скорости из списка,
- `N/E/O`,
- `1` и `2` stop bits,
- адреса `1..247`,
- функции `1, 2, 3, 4`,
- нужные регистры, например `0-32` или `0,1,2,100,256`.

Для первого прохода разумно:

1. Выбрать правильный COM порт.
2. Оставить все скорости.
3. Оставить все `Parity`.
4. Оставить `stop bits = 1`.
5. Поставить регистры `0-32`.
6. Запустить скан.

Если ответов нет, потом расширять:

1. Добавить `stop bits = 2`.
2. Увеличить набор регистров.
3. Сузить адресный диапазон, если есть подозрение на конкретный slave ID.

## Режим server на ПК2

Рекомендуемые шаги:

1. Подключить RS485 адаптер и убедиться, что появился COM порт.
2. В `server` выбрать этот COM.
3. Выставить скорость/parity/stop bits, если они уже известны.
4. `Listen IP` оставить `0.0.0.0`.
5. Порт, например `9000`.
6. Разрешить этот порт в Windows Firewall.

Если параметры RS485 устройства неизвестны, сначала найти их через `modbus scan`.

## Режим client на ПК1

1. Указать белый IP ПК2.
2. Указать тот же TCP порт, что в `server`.
3. Выбрать локальный виртуальный COM.
4. Открыть второй COM из виртуальной пары в своей Modbus-программе.

## Что я советую по сети

Так как белый IP есть у ПК2, а у ПК1 нет, базовый вариант уже рабочий:

- `client` на ПК1 сам инициирует исходящее подключение к `server` на ПК2,
- пробрасывать порт на ПК1 не нужно.

Если нужен более надежный и безопасный вариант, лучше VPN.

Лучшие практичные варианты:

1. `Tailscale`
   Самый простой вариант для двух ПК. Обычно не требует ручной настройки маршрутов и дает стабильную частную сеть.
2. `WireGuard`
   Тоже хороший вариант, но чуть больше ручной настройки.

Для текущей задачи я бы рекомендовал именно `Tailscale`: быстрее поднять, проще поддерживать, меньше возни с NAT и firewall.
